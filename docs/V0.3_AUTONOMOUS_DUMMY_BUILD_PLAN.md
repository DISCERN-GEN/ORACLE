# ORACLE v0.3 — Autonomous Dummy-Test Build Plan

## Target

Deliver a private, single-owner ORACLE build that can run a 12-hour autonomous paper-only test against confirmed live Polymarket markets. The test uses a simulated bankroll only. No wallet signer, private key, deposit, venue order submission, or live execution component is in scope.

## Fixed test parameters

- Wallet discovery target: 5,000 unique candidate wallets for the initial test; architecture remains configurable up to 10,000.
- Market universe: currently active, non-closed markets; market eligibility additionally requires valid outcomes, a fresh CLOB book, executable opposing-side depth, and valid market rules.
- Test duration: exactly 12 hours, UTC timestamps.
- Simulated initial bankroll: 10,000 units (not currency or funds).
- All decisions and simulated execution are autonomous after the owner starts the session.
- No-trade is a valid and expected decision when evidence, freshness, liquidity, or risk checks fail.

## Required stages

### A. Wallet candidate discovery

1. Seed from public leaderboard pages with cursor pagination.
2. Expand from active-market trade activity and wallet addresses found in public trade records, where supported by the public API.
3. Deduplicate and normalize addresses; preserve discovery source and timestamps.
4. Persist cursor/checkpoint state so a restart does not silently restart or skip the scan.
5. Report target, discovered unique count, source mix, errors, API coverage and unresolved pages. A target of 5,000 is not considered met unless 5,000 unique, valid addresses are persisted.

### B. Wallet evidence reconstruction and ranking

1. Retrieve wallet trade history within documented API limits and retain raw source references.
2. Normalize trades, deduplicate by stable trade identifier and reconstruct inventory using explicit opening-balance assumptions.
3. Track realized P&L, unrealized P&L only when marked, fees, turnover, unmatched sells, market concentration and history coverage.
4. Do not call headline P&L, ROI or win rate proof of skill.
5. Score using the blueprint's proposed weights: out-of-sample skill 25%, risk-adjusted net return 20%, closing-line value 15%, consistency 15%, timing 10%, liquidity/capacity 10%, data quality 5%.
6. Missing metrics remain missing. The composite must show observed-weight coverage and confidence; incomplete accounts cannot be promoted to verified skilled traders.
7. Use Bayesian shrinkage, event/market-cluster bootstrap, multiple-testing correction and chronological out-of-sample validation before a wallet can be described as statistically skilled.

### C. Live market intelligence

1. Discover active markets continuously and verify not closed/resolved/suspended.
2. Validate outcome labels, token IDs and resolution rules.
3. Subscribe to live CLOB WebSocket updates and reconcile with REST snapshots.
4. Enforce quote-age and depth thresholds; stale or empty books block paper orders.
5. Persist source timestamps, receive timestamps, sequence/reconnect gaps and raw payload provenance.

### D. Independent probability and evidence engine

1. Version every model and record its inputs and point-in-time evidence.
2. Establish baseline market-implied probabilities and independent model estimates.
3. Validate with chronological splits and avoid look-ahead leakage.
4. Record calibration (Brier/log loss), uncertainty, model disagreement and out-of-domain status.
5. Unvalidated previews may generate research/watch signals only, never order-authorizing forecasts.

### E. Opportunity and risk engine

1. Scan eligible markets for directional mispricing and complete-set opportunities.
2. Evaluate executable depth, spread, fees, slippage and settlement/rules risk.
3. Require complete outcome coverage and verified exhaustive outcomes before classifying a complete-set arbitrage.
4. Apply deterministic risk limits independently of the agent/LLM; the agent cannot alter limits.
5. Include event/category correlation, concentration, bankroll, drawdown and unresolved reconciliation checks.
6. The system must be allowed to refuse every opportunity.

### F. Autonomous paper execution

1. Persistent agent schedules bounded research and analysis cycles without per-decision owner approval.
2. Typed tools return structured, validated data; model/LLM text is never itself an execution authorization.
3. Each order intent references market snapshot, forecast/model, evidence, opportunity, risk decision and idempotency key.
4. Paper broker simulates conservative fills only against visible opposing-side depth; no invented liquidity or guaranteed fills.
5. Implement partial fills, unfilled remainder, cancellation/expiry, fees, cash/position ledger and settlement handling.
6. Restart recovery reconciles persisted paper orders, fills, positions and cash before permitting new exposure.

### G. 12-hour observability and report

Record heartbeat, data completeness, wallet scan progress, model status, opportunities, decisions, risk rejections, paper orders/fills, P&L, drawdown, exposure, API errors, latency, restarts and audit-chain state. Final report must distinguish system uptime, data coverage, forecast quality and simulated performance. No profitability conclusion from a single 12-hour run.

## Hard safety invariants

- Paper mode is enforced server-side; no live order/signing path exists in this build.
- No private signing credentials are accepted or stored.
- No order without fresh market data, valid market rules, model provenance and deterministic risk approval.
- No autonomous modification of risk limits.
- No silent zero-filling of missing data.
- No wallet classified as skilled on headline profit alone.
- No new exposure while reconciliation is unresolved.
- Every decision and financial state transition is append-only audited.

## Build order and gates

1. **Foundation gate:** Compose, migrations, auth, storage, restart and API integration tests pass.
2. **Wallet gate:** 5,000 unique registry entries plus measurable source coverage; trade reconstruction and evidence-aware scoring tested.
3. **Market-data gate:** live WebSocket/REST reconciliation, freshness, depth and recovery tests pass.
4. **Forecast gate:** independent model baseline, point-in-time provenance, chronological validation and calibration reports exist.
5. **Opportunity/risk gate:** executable-cost calculations, correlated exposure limits, rejection tests and no-trade tests pass.
6. **Execution gate:** autonomous paper lifecycle, idempotency, partial fills, fees, restart recovery and reconciliation pass.
7. **Acceptance gate:** dry-run integration test and all negative/security tests pass before starting the 12-hour live-data paper session.

## Current implementation status after v0.2 baseline

- v0.2 has leaderboard-only wallet registry seeding, normalized trade reconstruction foundations, Bayesian evidence utilities, selected-market REST sampling, order-book snapshots, directional opportunity calculations, paper risk/broker foundations and an observation controller.
- Added in this build iteration: `oracle_platform/wallet_scoring.py`, an evidence-aware provisional wallet score that retains missing metrics as null, computes a conservative Wilson lower bound for consistency when resolved-position sample data is supplied, and refuses to label wallets statistically skilled without out-of-sample evidence. Added tests.
- v0.5 adds resumable multi-source wallet discovery, bounded per-wallet full-history trade-feed ingestion, raw-row provenance, fee-unknown handling, and database-backed provisional evidence profiles. Live 5,000-wallet coverage has not been demonstrated. Complete account activity reconciliation, resolved-position data and independent wallet skill metrics remain outstanding.
- Independently validated forecasts, persistent autonomous planning, automatic paper order generation, WebSocket/REST reconciliation and complete restart-safe execution remain outstanding.
- Therefore this package is a further engineering increment, **not yet a candidate for the 12-hour autonomous acceptance test**.
