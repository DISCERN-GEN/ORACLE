# ORACLE v0.2 — Implemented Scope and Remaining Work

This document distinguishes the capabilities present in the current source tree from the complete ORACLE target architecture in the original source package.

## Present in v0.2

- Private single-owner FastAPI API with bearer-token authentication and a startup guard against the example/weak owner token.
- PostgreSQL initial schema for core wallet, market, source, event, claim, forecast, opportunity, risk, order, settlement, memory, audit, paper-session, paper-order, paper-fill and account-snapshot entities.
- Public read-only Polymarket adapters for Gamma market metadata, CLOB books, Data API v2 leaderboard/trades and the official geoblock endpoint. GET retries, a bounded concurrency semaphore and cursor-aware paging are included.
- Wallet-registry seeding from the public leaderboard. A separate average-cost trade reconstruction module handles supplied normalized fills and explicitly flags missing opening balances, incomplete coverage, unmatched sells and absent marks.
- Bayesian Beta-prior and likelihood-ratio updates with independence-group duplicate protection; Brier score and log-loss evaluation utilities.
- RSS/Atom ingestion for owner-configured HTTPS feeds, source reliability tiers, content hashes, observed/published timestamps, a payload size cap and explicit provenance. Feed entries remain leads, not verified facts.
- Directional opportunity evaluation using executable order-book depth and fee assumptions; complete-set evaluation requires exact outcome coverage and explicit exhaustive-outcome/settlement attestations.
- Constrained mean-variance approximation to portfolio Kelly, with single/total caps, covariance validation and bounded projected optimisation.
- Deterministic paper risk checks and conservative paper fills only against visible opposing-side depth, with minimum-size/tick-size checks and owner-attested fee assumptions.
- Persistent forecast records (always marked unvalidated), news source documents, paper sessions, simulated fills, account snapshots and append-only audit hash-chain verification.
- Timed 12-hour live-data observation controller, private dashboard shell, Docker Compose deployment configuration and helper scripts.
- Unit tests for the implemented components.

## Not yet implemented or integrated into a complete autonomous lifecycle

- Full discovery to 10,000 wallets across leaderboards, active market activity and counterparty relationships; automated polling/reconstruction for every wallet; transfers, redemptions, rewards and full economic P&L normalization.
- Automated WebSocket ingestion, REST reconciliation, raw source archive, robust cursor checkpointing, request/rate-limit metrics and full completeness monitoring.
- Scheduled RSS source registry and source-licensing review; claim extraction, corroboration/dependency graph, contradiction analysis, event graph and exact market resolution mapping.
- Independent trained/statistical/domain-specific forecasting providers, time-split training, calibrated intervals, model cards, prospective promotion rules and ensemble evaluation. Evidence-based previews in v0.2 are explicitly unvalidated.
- Automated mispricing scanner, full related-market equivalence checks, executable multi-leg complete-set sequencing, legging-risk controls and orderbook-derived fee/slippage calibration.
- Full covariance-aware portfolio risk using validated joint outcome scenarios, market/event/category concentration and drawdown controls. Current allocation is a mean-variance approximation, not exact joint-outcome Kelly.
- Persistent autonomous research planner with LLM-based investigation, typed tool execution, long-term memory retrieval, evidence challenges, strategy learning and autonomous paper order generation. The current agent only polls live market metadata and selected books; it does not invent forecasts or place trades by itself.
- Dashboard views for wallets, news/events, forecasts, opportunities, positions, portfolio risk, metrics and audit exploration.
- Prometheus/Grafana dashboards, OpenTelemetry tracing, backup/restore automation, alerting, incident drills and production deployment verification.
- Any live signing, deposits, real-money execution, or live execution gateway. No signer or live-order route exists.

## What v0.2's 12-hour controller currently tests

Once deployed, the session controller can run a timed live-data observation session: poll open market metadata, sample selected books, persist observations, record heartbeat/errors and mark interrupted sessions failed on process restart. It can accept owner-supplied paper proposals through a separate API route, but does not generate autonomous paper orders from independently validated ORACLE forecasts.

Therefore, a v0.2 12-hour observation session is **not** the full-system acceptance test described in `12_HOUR_TEST_PROTOCOL.md`.
