# ORACLE v0.1 — Implemented Scope and Remaining Work

This document prevents the first engineering increment from being mistaken for the complete ORACLE target described in the source package.

## Implemented in this increment

- Private single-owner FastAPI API with bearer-token authentication.
- PostgreSQL initial schema for core intelligence, forecasts, opportunities, risk, paper orders, fills, audit and memory.
- Public, read-only Polymarket adapters for Gamma market metadata, CLOB order books, Data API v2 leaderboard/trades and the official geoblock endpoint.
- Wallet-registry seeding from the public leaderboard (not full discovery or reconstruction).
- Decimal-based expected-value, fractional-Kelly, Bayesian-update, Brier/log-loss and weighted wallet-score primitives.
- Deterministic paper risk checks with fail-closed controls.
- Conservative paper fills only against visible opposing-side book depth, with min-size, tick-size and owner-attested fee-assumption checks.
- Persistent session records, UTC session bounds, heartbeat, restart-failure marking, order idempotency, simulated fills, account snapshots and an audit hash chain.
- A private dashboard shell and a 12-hour live-data observation session controller.
- Unit tests for the implemented quantitative, paper-broker, risk, session and Polymarket pagination logic.

## Not yet implemented or integrated

- Full wallet discovery to 10,000 through multiple sources, historical trade/position reconstruction, fees/transfers/redemptions, P&L, closing-line value and statistical ranking.
- WebSocket streaming, robust REST/WebSocket reconciliation, raw archive retention, comprehensive rate-limit/retry policy and measured ingestion completeness.
- News-source connectors, source licensing registry, claims extraction, contradiction analysis, event graph and exact market-resolution mapping.
- Production independent forecast models, calibration evaluation, specialist models and a validated ensemble. The current probability request is an owner-supplied paper-test input, not a verified ORACLE forecast.
- Automated opportunity scanner, complete-set/related-market arbitrage verification, fee/slippage calibration and correlation-aware portfolio optimisation.
- Full autonomous planning/research/memory lifecycle and autonomous simulated order generation. The current agent samples live market metadata and selected books; it does not invent forecasts or place trades by itself.
- Prometheus/Grafana dashboards, OpenTelemetry tracing, backup/restore automation, incident alerting and deployment/recovery drills.
- Any live signing, deposits, real-money execution, or live execution gateway. No live-order route or signer is included.

## What the 12-hour controller currently proves

Once deployed, the current controller can time a 12-hour paper-mode observation session, poll open market metadata and selected order books, persist observations, update heartbeats, record errors and mark interrupted sessions failed after a process restart. It does **not** yet validate the complete target system or autonomously generate paper trades.

The full 12-hour acceptance protocol in `12_HOUR_TEST_PROTOCOL.md` remains the target gate and must not be marked passed until all listed subsystems have been implemented, integrated and measured.

## Immediate engineering sequence

1. Verify container deployment, schema migration and private authentication on the target host.
2. Complete robust market/data ingestion, retries, raw payload archive and ingestion quality metrics.
3. Complete the 10,000-wallet discovery and historical reconstruction pipeline.
4. Implement news/event source connectors and the evidence graph.
5. Implement and validate independent forecasting models; no model enters paper automation without a model card and prospective evaluation.
6. Implement opportunity detection, executable net-EV calculations, arbitrage verification and portfolio risk.

8. Add operational monitoring, backup/restore and recovery drills.

10. Keep live execution disabled until separate venue, local legal, security, model and owner-approval gates are satisfied.
